# 字段映射配置分析报告

## 1. 概述

本报告分析 Maybe 应用中外部数据导入时，字段映射配置如何将外部数据转换为系统内部字段，以及余额表模型、交易模型和汇率模型在多货币场景下的处理差异。

## 2. 字段映射配置来源

### 2.1 映射模型架构

字段映射配置由 `Import::Mapping` 基类及其子类实现，类图如下：

```
Import::Mapping (基类)
├── Import::CategoryMapping  # 分类映射
├── Import::TagMapping       # 标签映射
```

### 2.2 配置来源链路

映射配置的数据来源遵循以下链路：

```
CSV文件列 → Import::Row → Import::Mapping → 系统内部模型
```

**CSV 文件解析阶段**（[import.rb:L98-108](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/import.rb#L98-L108)）：
- `raw_file_str` 存储原始 CSV 字符串
- `parse_csv_str` 方法使用指定分隔符解析 CSV
- `generate_rows_from_csv` 将 CSV 行转换为 `Import::Row` 记录

**映射同步阶段**（[import.rb:L156-172](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/import.rb#L156-L172)）：
```ruby
def sync_mappings
  transaction do
    mapping_steps.each do |mapping_class|
      mappables_by_key = mapping_class.mappables_by_key(self)
      updated_mappings = mappables_by_key.map do |key, mappable|
        mapping = mappings.find_or_initialize_by(key: key, import: self, type: mapping_class.name)
        mapping.mappable = mappable
        mapping.create_when_empty = key.present? && mappable.nil?
        mapping
      end
      updated_mappings.each { |m| m.save(validate: false) }
    end
  end
end
```

## 3. 余额表模型与交易模型的映射结果处理差异

### 3.1 模型层级结构

```

└── delegated_type :entryable, types: Entryable::TYPES
    ├── Transaction (include Entryable, Transferable, Ruleable)

Balance (include Monetizable)
└── belongs_to :account
```

### 3.2 交易模型（Transaction）的映射接收

**入口文件**：[transaction_import.rb](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/transaction_import.rb#L2-L33)

```ruby
def import!
  transaction do
    mappings.each(&:create_mappable!)  # 先创建映射的资源

    transactions = rows.map do |row|
      mapped_account = if account
        account
      else
        mappings.accounts.mappable_for(row.account)  # 通过映射查找账户
      end

      category = mappings.categories.mappable_for(row.category)  # 分类映射
      tags = row.tags_list.map { |tag| mappings.tags.mappable_for(tag) }.compact  # 标签映射

      Transaction.new(
        category: category,
        tags: tags,
        entry: Entry.new(
          account: mapped_account,
          date: row.date_iso,
          amount: row.signed_amount,    # 已处理符号约定
          name: row.name,
          currency: row.currency,       # 直接使用 CSV 中的货币
          notes: row.notes,
          import: self
        )
      )
    end

    Transaction.import!(transactions, recursive: true)
  end
end
```

**特点**：
1. **直接写入**：Transaction 直接从 `Import::Row` 获取数据，映射结果用于查找关联资源
2. **货币直接映射**：`currency` 字段直接从 CSV 的 `currency` 列获取
3. **符号约定处理**：`signed_amount` 方法处理正负号约定（[row.rb:L25-60](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/import/row.rb#L25-L60)）

### 3.3 余额表模型（Balance）的映射接收

**入口文件**：[balance_sheet.rb](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/balance_sheet.rb) 和 [account_import.rb](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/account_import.rb)

**账户导入处理**（AccountImport）：
```ruby
def import!
  transaction do
    rows.each do |row|
      mapping = mappings.account_types.find_by(key: row.entity_type)
      accountable_class = mapping.value.constantize  # 从映射获取账户类型

      account = family.accounts.build(
        name: row.name,
        balance: row.amount.to_d,     # CSV 的 amount 直接作为余额
        currency: row.currency,         # 直接使用 CSV 货币
        accountable: accountable_class.new,
        import: self
      )

      manager = Account::OpeningBalanceManager.new(account)
      result = manager.set_opening_balance(balance: row.amount.to_d)
    end
  end
end
```

### 3.4 核心差异对比

| 特性 | 交易模型 (Transaction) | 余额模型 (Balance/Account) |
|------|----------------------|---------------------------|
| **映射用途** | 查找关联资源（category, tags, account） | 查找账户类型（accountable_class） |
| **数据写入** | Entry + Transaction 双重写入 | Account 及其初始余额 |
| **货币处理** | 直接从 CSV 读取，不转换 | 直接从 CSV 读取，不转换 |
| **符号约定** | 通过 `signed_amount` 处理 | 通过 `OpeningBalanceManager` 处理 |
| **金额字段** | `amount` | `balance` |
| **验证时机** | 创建时验证 | 创建后设置初始余额 |

### 3.5 Enrichable 模块的作用

两个模型都通过 `include Enrichable` 获得了字段锁定和富化能力：

**锁定机制**（[enrichable.rb:L53-73](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/concerns/enrichable.rb#L53-L73)）：
- `lock_attr!`: 锁定单个属性，防止后续覆盖
- `lock_saved_attributes!`: 锁定所有已保存的属性
- 用于区分用户手动修改和系统/规则自动修改

**富化机制**（[enrichable.rb:L26-51](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/concerns/enrichable.rb#L26-L51)）：
- `enrich_attributes`: 根据来源（source）更新属性
- 跳过已锁定、已忽略或值未变化的属性

## 4. 汇率模型在多货币导入场景下的介入时机与换算逻辑

### 4.1 汇率模型架构

**模型定义**：[exchange_rate.rb](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/exchange_rate.rb)
```ruby
class ExchangeRate < ApplicationRecord
  include Provided

  validates :from_currency, :to_currency, :date, :rate, presence: true
  validates :date, uniqueness: { scope: %i[from_currency to_currency] }
end
```

**数据提供者**：[exchange_rate/provided.rb](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/exchange_rate/provided.rb)
```ruby
module ExchangeRate::Provided
  def find_or_fetch_rate(from:, to:, date: Date.current, cache: true)
    rate = find_by(from_currency: from, to_currency: to, date: date)
    return rate if rate.present?

    response = provider.fetch_exchange_rate(from: from, to: to, date: date)
    ExchangeRate.find_or_create_by!(...) if cache
    rate
  end
end
```

### 4.2 介入时机

#### 4.2.1 导入阶段（Import 时）

**不介入**：在 `TransactionImport`、`TradeImport`、`AccountImport` 的 `import!` 方法执行时，汇率模型**不会**被调用。

原因：导入阶段只负责将 CSV 数据写入系统，货币字段直接使用 CSV 中的值，不进行换算。

#### 4.2.2 同步阶段（Sync 时）

**介入点 1：Account::MarketDataImporter**（[account/market_data_importer.rb](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/account/market_data_importer.rb#L13-L43)）

```ruby
def import_exchange_rates
  return unless needs_exchange_rates?

  # 1. ENTRY-BASED PAIRS – 账户中与账户货币不同的条目货币
  account.entries
         .where.not(currency: account.currency)
         .group(:currency)
         .minimum(:date)
         .each do |source_currency, date|
    # 获取从 source_currency 到 account.currency 的汇率
    ExchangeRate.import_provider_rates(from: source_currency, to: account.currency, ...)
  end

  # 2. ACCOUNT-BASED PAIR – 账户货币到家族货币
  if foreign_account?
    ExchangeRate.import_provider_rates(from: account.currency, to: account.family.currency, ...)
  end
end
```

**介入点 2：MarketDataImporter**（[market_data_importer.rb](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/market_data_importer.rb#L37-L55)）

```ruby
def import_exchange_rates
  required_exchange_rate_pairs.each do |pair|
    ExchangeRate.import_provider_rates(
      from: pair[:source],
      to: pair[:target],
      start_date: start_date,
      end_date: end_date
    )
  end
end

# 汇率需求计算逻辑
def required_exchange_rate_pairs
  pair_dates = {}

  # 1. Entry-based: 从 Entry 的最早日期开始需要汇率
  Entry.joins(:account)
       .where.not("entries.currency = accounts.currency")
       .group("entries.currency", "accounts.currency")
       .minimum("entries.date")
       .each { |(source, target), date| pair_dates[[source, target]] = date }

  # 2. Account-based: 账户货币与家族货币不同时
  Account.joins(:family)
         .where.not("families.currency = accounts.currency")
         .select(...)
         .find_each { |account| pair_dates[[account.source, account.target]] = ... }
end
```

#### 4.2.3 展示阶段（Balance Sheet 计算时）

**介入点 3：Accountable.balance_money**（[accountable.rb:L59-68](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/app/models/concerns/accountable.rb#L59-L68)）

```ruby
def balance_money(family)
  family.accounts
        .active
        .joins(sanitize_sql_array([
          # LEFT JOIN exchange_rates ON exchange_rates.date = current_date
          #   AND accounts.currency = exchange_rates.from_currency
          #   AND exchange_rates.to_currency = family_currency
          "LEFT JOIN exchange_rates ON exchange_rates.date = :current_date
           AND accounts.currency = exchange_rates.from_currency
           AND exchange_rates.to_currency = :family_currency",
          { current_date: Date.current.to_s, family_currency: family.currency }
        ]))
        .where(accountable_type: self.name)
        .sum("accounts.balance * COALESCE(exchange_rates.rate, 1)")  # 汇率换算
end
```

### 4.3 换算逻辑

#### 4.3.1 汇率存储结构

```
ExchangeRate {
  from_currency: String  # 源货币 (如 "EUR")
  to_currency: String   # 目标货币 (如 "USD")
  date: Date            # 汇率日期
  rate: Decimal         # 汇率值 (from_currency -> to_currency)
}
```

#### 4.3.2 汇率获取策略

**时机**：按需获取（lazy loading）+ 预获取（preloading）

1. **预获取**：`MarketDataImporter` 在每日同步时预获取所有需要的汇率
2. **按需获取**：`ExchangeRate.find_or_fetch_rate` 在需要时从 provider 获取
3. **Gap filling**：`ExchangeRate::Importer` 使用 LOCF（Last Observation Carried Forward）策略填充缺失日期

#### 4.3.3 换算公式

```ruby
# 换算到目标货币
target_amount = source_amount * exchange_rate

# 示例：EUR 100 -> USD，汇率 1.10
# USD amount = 100 * 1.10 = 110 USD
```

#### 4.3.4 Money 类的换算方法

[lib/money.rb](file:///d:/fz/0508-1/solo-dogfeeding/code/122-maybe/lib/money.rb#L42-L55)：
```ruby
def exchange_to(other_currency, date: Date.current, fallback_rate: nil)
  iso_code = currency.iso_code
  other_iso_code = Money::Currency.new(other_currency).iso_code

  if iso_code == other_iso_code
    self  # 同货币直接返回
  else
    exchange_rate = store.find_or_fetch_rate(
      from: iso_code,
      to: other_iso_code,
      date: date
    )&.rate || fallback_rate

    raise ConversionError unless exchange_rate
    Money.new(amount * exchange_rate, other_iso_code)
  end
end
```

### 4.4 多货币场景处理流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    多货币导入处理流程                              │
├─────────────────────────────────────────────────────────────────┤
│  1. Import 阶段                                                  │
│     ├── TransactionImport.import! 执行                           │
│     ├── Entry.currency = CSV.currency (不做换算)                   │
│     └── ExchangeRate 不介入                                       │
├─────────────────────────────────────────────────────────────────┤
│  2. Sync 阶段                                                    │
│     ├── Account::MarketDataImporter.import_exchange_rates         │
│     │   └── 为 Entry.currency ≠ account.currency 的货币对获取汇率   │
│     └── MarketDataImporter.import_exchange_rates                  │
│         └── 为所有账户和家族的货币差异获取汇率                      │
├─────────────────────────────────────────────────────────────────┤
│  3. 展示阶段                                                     │
│     ├── BalanceSheet.net_worth 计算                              │
│     │   └── Accountable.balance_money 使用 JOIN exchange_rates   │
│     │       └── SELECT balance * COALESCE(exchange_rates.rate, 1) │
│     └── Holding.avg_cost 计算                                     │
│         └── LEFT JOIN exchange_rates ON entries.date              │
└─────────────────────────────────────────────────────────────────┘
```

### 4.5 关键设计决策

1. **导入时不换算**：CSV 中的货币值原样写入，保持数据精确性
2. **同步时获取汇率**：在后台预获取所有需要的汇率
3. **展示时换算**：使用 COALESCE 策略，无汇率时默认 rate = 1
4. **LOCF 填充**：缺失汇率时使用最近可用汇率

## 5. 总结

### 5.1 字段映射配置要点

- 映射配置存储在 `Import::Mapping` 及其子类中
- 通过 `mapping_steps` 方法定义每种导入类型的映射类型
- 映射结果通过 `mappable_for(key)` 方法查找系统资源

### 5.2 模型处理差异

| 维度 | Transaction | Balance/Account |
|------|-------------|-----------------|
| 映射用途 | 查找关联资源 | 确定账户类型 |
| 金额字段 | `amount` | `balance` |
| 货币处理 | 直接写入 | 直接写入 |
| 时机 | Import 时 | Import + Sync + Display |

### 5.3 汇率介入时机

1. **Import 阶段**：不介入
2. **Sync 阶段**：通过 `MarketDataImporter` 和 `Account::MarketDataImporter` 预获取汇率
3. **Display 阶段**：通过 SQL JOIN 在查询时换算，或使用 `Money#exchange_to` 方法
