## 二、分类规则层详解

### 2.1 Rule 核心模型 (`app/models/rule.rb`)

**核心职责**：
- 管理规则的生命周期（创建、验证、应用）
- 组合多个 Condition（条件）和 Action（动作）
- 通过 Registry 模式支持不同资源类型的规则

**关键代码**：
```ruby
# 规则应用入口
def apply(ignore_attribute_locks: false)
  actions.each do |action|
    action.apply(matching_resources_scope, ignore_attribute_locks: ignore_attribute_locks)
  end
end

# 资源匹配范围（通过 Registry 实现）
def matching_resources_scope
  scope = registry.resource_scope
  conditions.each { |condition| scope = condition.prepare(scope) }
  conditions.each { |condition| scope = condition.apply(scope) }
  scope
end
```

### 2.2 Transaction 资源注册表 (`app/models/rule/registry/transaction_resource.rb`)

**支持的条件过滤器**：
- `TransactionName` - 交易名称匹配
- `TransactionAmount` - 交易金额范围
- `TransactionMerchant` - 商户匹配

**支持的动作执行器**：
- `SetTransactionCategory` - 设置分类
- `SetTransactionTags` - 设置标签
- `SetTransactionMerchant` - 设置商户
- `SetTransactionName` - 设置名称
- `AutoCategorize` - AI 自动分类（可选）
- `AutoDetectMerchants` - AI 商户检测（可选）

### 2.3 SetTransactionCategory 执行器 (`app/models/rule/action_executor/set_transaction_category.rb`)

**分类标注核心流程**：

```ruby
def execute(transaction_scope, value: nil, ignore_attribute_locks: false)
  category = family.categories.find_by_id(value)
  
  # 1. 属性锁定检查：保护用户已手动修改的属性
  unless ignore_attribute_locks
    scope = transaction_scope.enrichable(:category_id)
  end

  # 2. 批量应用分类标注
  scope.each do |txn|
    txn.enrich_attribute(
      :category_id,
      category.id,
      source: "rule"  # 标记来源为规则引擎
    )
  end
end
```

### 2.4 Enrichable 属性增强机制 (`app/models/concerns/enrichable.rb`)

**核心设计理念**：
- **属性锁定**：用户编辑的属性具有最高优先级，防止规则覆盖
- **来源追踪**：记录每个属性修改的来源（rule/plaid/user等）
- **变更日志**：通过 `DataEnrichment` 记录所有自动修改

**关键方法**：
```ruby
# 锁定属性（用户修改后自动锁定）
def lock_attr!(attr)
  update!(locked_attributes: locked_attributes.merge(attr.to_s => Time.current))
end

# 检查属性是否可被规则修改
def enrichable?(attr)
  !locked?(attr)
end

# 增强属性（带来源追踪）
def enrich_attribute(attr, value, source:, metadata: {})
  # 仅当属性未锁定且值发生变化时才更新
  return if locked?(attr) || self[attr.to_s] == value
  
  ActiveRecord::Base.transaction do
    self.send("#{attr}=", value)
    log_enrichment(attribute_name: attr, attribute_value: value, source: source, metadata: metadata)
    save
  end
end
```

## 三、数据实体层详解

### 3.1 实体关系图

```
Family (1)
  ├─ Account (N)
  │   └─ Entry (N)
  │       ├─ amount (货币值，负=收入，正=支出)
  │       ├─ date (交易日期)
  │       ├─ currency (货币类型)
  │       └─ entryable_type: "Transaction"
  │           └─ Transaction
  │               ├─ category_id (外键 → Category)
  │               ├─ merchant_id
  │               └─ kind (交易类型过滤)
  └─ Category (N)
      ├─ name
      ├─ classification (income/expense)
      ├─ parent_id (支持两级分类)
      └─ color
```

### 3.2 Entry 核心模型 (`app/models/entry.rb`)

**分类判断逻辑**：
```ruby
def classification
  amount.negative? ? "income" : "expense"
end
```

**注意**：Entry 层的 classification 是基于金额符号的**二次判断**，与 Category 的 classification 可能不一致，SQL 查询中使用的是 Entry 层判断。

### 3.3 Transaction 模型 (`app/models/transaction.rb`)

**交易类型过滤枚举**：
```ruby
enum :kind, {
  standard: "standard",           # 常规交易 - 计入统计
  funds_movement: "funds_movement", # 资金划转 - 排除
  cc_payment: "cc_payment",       # 信用卡还款 - 排除
  loan_payment: "loan_payment",   # 贷款还款 - 计入
  one_time: "one_time"            # 一次性交易 - 排除
}
```

**关键过滤条件**（统计时排除的类型）：
```sql
WHERE at.kind NOT IN ('funds_movement', 'one_time', 'cc_payment')
  AND ae.excluded = false
```

## 四、统计汇总层详解

### 4.1 IncomeStatement 入口 (`app/models/income_statement.rb`)

**缓存策略**：
```ruby
# 基于 entries 的 updated_at 生成缓存版本号
def entries_cache_version
  @entries_cache_version ||= begin
    ts = entries.maximum(:updated_at)
    ts.present? ? ts.to_i : 0
  end
end

# 缓存键示例
["income_statement", "totals_query", family.id, sql_hash, family.entries_cache_version]
```

### 4.2 Totals 直接聚合 (`app/models/income_statement/totals.rb`)

**核心 SQL 查询**：
```sql
SELECT
  c.id as category_id,
  c.parent_id as parent_category_id,
  CASE WHEN ae.amount < 0 THEN 'income' ELSE 'expense' END as classification,
  ABS(SUM(ae.amount * COALESCE(er.rate, 1))) as total,  -- 汇率转换
  COUNT(ae.id) as transactions_count
FROM (#{transactions_scope.to_sql}) at
JOIN entries ae ON ae.entryable_id = at.id AND ae.entryable_type = 'Transaction'
LEFT JOIN categories c ON c.id = at.category_id
LEFT JOIN exchange_rates er ON (
  er.date = ae.date AND
  er.from_currency = ae.currency AND
  er.to_currency = :target_currency
)
WHERE at.kind NOT IN ('funds_movement', 'one_time', 'cc_payment')
  AND ae.excluded = false
GROUP BY c.id, c.parent_id, CASE WHEN ae.amount < 0 THEN 'income' ELSE 'expense' END;
```

**聚合逻辑要点**：
1. **多币种支持**：通过 `exchange_rates` 表转换为家庭本位币
2. **父子分类聚合**：同时返回 `category_id` 和 `parent_category_id`
3. **分类二次判断**：使用 `CASE WHEN ae.amount < 0` 判断收入/支出
4. **交易过滤**：排除划转、一次性交易、信用卡还款

### 4.3 CategoryStats 分类统计 (`app/models/income_statement/category_stats.rb`)

**按时间段计算中位数/平均值**：
```sql
WITH period_totals AS (
  SELECT
    c.id as category_id,
    date_trunc(:interval, ae.date) as period,  -- 按时间段分组（月/周）
    CASE WHEN ae.amount < 0 THEN 'income' ELSE 'expense' END as classification,
    SUM(ae.amount * COALESCE(er.rate, 1)) as total
  FROM transactions t
  JOIN entries ae ON ae.entryable_id = t.id AND ae.entryable_type = 'Transaction'
  JOIN accounts a ON a.id = ae.account_id
  LEFT JOIN categories c ON c.id = t.category_id
  LEFT JOIN exchange_rates er ON (...)
  WHERE a.family_id = :family_id
    AND t.kind NOT IN ('funds_movement', 'one_time', 'cc_payment')
    AND ae.excluded = false
  GROUP BY c.id, period, CASE WHEN ae.amount < 0 THEN 'income' ELSE 'expense' END
)
SELECT
  category_id,
  classification,
  ABS(PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY total)) as median,  -- 中位数
  ABS(AVG(total)) as avg                                                -- 平均值
FROM period_totals
GROUP BY category_id, classification;
```

**用途**：
- 预算模块的月度支出中位数预测
- 支出趋势分析基准线

### 4.4 FamilyStats 家庭整体统计 (`app/models/income_statement/family_stats.rb`)

与 CategoryStats 类似，但不按分类分组，直接计算家庭整体的收入/支出中位数/平均值。

### 4.5 Budget 预算计算 (`app/models/budget.rb`)

**预算与分类统计的关联**：
```ruby
# 使用中位数作为预估支出
def estimated_spending
  income_statement.median_expense(interval: "month")
end

# 实际支出 = 该期间分类汇总
def actual_spending
  expense_totals.total
end

# 分类维度的实际支出
def budget_category_actual_spending(budget_category)
  expense_totals.category_totals.find { |ct| 
    ct.category.id == budget_category.category.id 
  }&.total || 0
end
```

### 5.1 数据流转时序图

```
     │                 │ ─────────────────>│                       │
     │                 │                   │ update category_id    │

     │                 │                   │                       │
     │                 │                   │ totals()              │
     │                 │                   │ <─────────────────────│

     │                 │                   │ ─────────────────────>│
     └─────────────────┘                   └───────────────────────┘
```

### 5.2 分类标注到统计聚合的关键路径

**路径 1：规则自动分类 → 统计**
```
1. Rule.apply()
   ↓
2. SetTransactionCategory.execute()
   ↓ 过滤条件：enrichable(:category_id)
3. Transaction.enrich_attribute(:category_id, value, source: "rule")
   ↓ 更新：category_id + locked_attributes
4. Family.entries_cache_version 失效（updated_at 更新）
   ↓
5. IncomeStatement.totals() 缓存失效
   ↓ 重新计算
6. Totals SQL 查询按 category_id GROUP BY
```

**路径 2：用户手动分类 → 统计**
```
1. 用户界面修改 Transaction.category_id
   ↓
2. Transaction.lock_saved_attributes!
   ↓ 锁定：category_id 加入 locked_attributes
3. Entry.touch → updated_at 更新
   ↓
4. entries_cache_version 递增
   ↓
5. 统计缓存失效，重新计算
```

### 5.3 跨模块数据流关键节点

| 节点 | 模块 | 数据传递 | 关键机制 |
|------|------|----------|----------|
| 规则匹配 | Rule::Registry | transactions_scope | 条件过滤 + 资源范围 |
| 属性增强 | Enrichable | category_id + source | 锁定机制 + 变更日志 |
| 时间戳传播 | Entry/Transaction | updated_at | touch: true |
| 缓存失效 | Family | entries_cache_version | max(entries.updated_at) |
| 汇率转换 | ExchangeRates | rate | 日期匹配 + 货币转换 |
| 分类聚合 | Totals | category_id + parent_id | GROUP BY + 父子汇总 |

## 六、设计特点与技术权衡

### 6.1 优点

1. **属性锁定机制**：保护用户手动编辑，避免规则覆盖
2. **来源可追溯**：DataEnrichment 记录所有自动修改历史
3. **高性能聚合**：原生 SQL 直接聚合，避免 ActiveRecord 开销
4. **智能缓存**：基于数据更新时间戳的缓存失效策略
5. **多币种支持**：实时汇率转换，统一本位币统计
6. **两级分类**：支持父子分类层级聚合

### 6.2 注意事项与潜在问题

1. **分类判断不一致风险**：
   - SQL 查询中使用 `CASE WHEN ae.amount < 0` 判断收入/支出
   - 可能与 Category.classification 不一致
   - **建议**：在 Category 模型中增加一致性校验

2. **NULL category_id 处理**：
   - 未分类交易的 category_id 为 NULL
   - 在 build_period_total 中通过 uncategorized_category 处理
   - 需要确保 NULL 分类在所有聚合场景中被正确处理

3. **父子分类双重计数**：
   ```ruby
   # 当前实现：父类总计 = 直接分配 + 子类汇总
   parent_category_total = totals.select { |t| t.category_id == category.id }&.sum(&:total) || 0
   children_totals = totals.select { |t| t.parent_category_id == category.id }&.sum(&:total) || 0
   category_total = parent_category_total + children_totals
   ```
   - **注意**：SQL 返回的是独立的行，Ruby 层进行父子合并

4. **缓存粒度**：
   - 整个 family 的 entries_cache_version 可能导致过度失效
   - 单一交易修改会导致所有统计缓存失效
